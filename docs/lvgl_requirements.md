# ESP-LEGO 板载触摸界面：预期效果与验收说明

## 1. 文档用途

本文描述 240 × 240 ST7789 + CST816D 屏幕在 Master 固件中的预期表现，重点回答：

- 没有从机时，屏幕能不能点、点了应该发生什么。
- Sensor 卡片和全屏详情页应该如何交互。
- 设备掉线、恢复和数据读取失败时应该显示什么。
- Sensor 与 Doorbell、蜂鸣器、舵机等非传感器设备应如何区分。
- 如何判断是“当前没有可点击对象”，还是触摸硬件/驱动没有工作。

## 2. 硬件与接线前提

- 主控：ESP32-S3。
- LCD：ST7789，SPI，240 × 240。
- Touch：CST816D，I²C 地址 `0x15`。
- 当前默认引脚（与 V1.0 物联网扩展板原理图一致，LCD 接 DevKitC-1 J1 的 17-20 脚）：
  - LCD_CS: GPIO11
  - LCD_DC: GPIO13
  - LCD_RST: -1（扩展板未布线，使用软件复位）
  - LCD_BL: -1（扩展板未布线，背光常亮）
  - LCD_MOSI: GPIO14
  - LCD_SCLK: GPIO12
  - TOUCH_SDA: GPIO16
  - TOUCH_SCL: GPIO17
  - TOUCH_RST: GPIO18
  - TOUCH_INT: GPIO21

触摸初始化失败不得阻止 LCD 和 LVGL 显示。此时屏幕仍应显示总览页，但所有触摸都不会生效，串口应输出一次明确的 CST816D 初始化错误。

## 3. 启动后的总览页

Master 启动后进入设备总览页。当前页面固定有 4 个卡片位置。

### 3.1 没有从机在线

- 4 个位置显示空占位内容。
- 空卡片处于 disabled 状态，不响应点击，也不会打开详情页。
- 因此，“一个从机都没连接时点击空卡片没有反应”是当前正常行为。
- 该现象只能说明没有可操作设备，不能证明触摸控制器正常或异常。

建议后续在空页面增加一行 `No devices online` 和一个触摸反馈点，使无从机时也可以肉眼验证触摸；这不是当前已经实现的功能。

### 3.2 从机上线

- 从机通过 ESP-NOW announce 被 Master 发现后，替换一个空卡片。
- announce 默认约每 3 秒发送一次，所以从机上电后卡片不是绝对立即出现。
- 卡片显示设备名称、模块 ID、在线状态和已有数据摘要。
- 只有真实存在的设备卡片可以点击。
- 当前总览最多显示 4 台设备；第 5 台及以后即使已被通信层登记，也不会出现在本屏幕。

### 3.3 如何确认触摸链路

按以下顺序判断：

1. 观察 Master 串口是否出现 `CST816D init done`。如果只有初始化错误，优先检查触摸 SDA/SCL/RST、供电和地址。
2. 连接至少一台从机，等待真实设备卡片出现。
3. 点击真实卡片；正常情况应进入全屏详情页。
4. 再测试右上角关闭按钮、上下滚动和右滑返回。

如果初始化成功且真实卡片仍无法点击，再检查坐标变换配置：`swap_xy`、`invert_x`、`invert_y` 和原始坐标范围。

## 4. Sensor 全屏详情页

### 4.1 进入和退出

- 点击真实的 Sensor 卡片后进入该模块的全屏详情页。
- 选择身份按稳定的 `module_id` 保存；其他设备上线、下线或卡片重排不应切换当前详情对象。
- 右上角固定关闭按钮返回总览。
- 在详情页做明确的水平右滑也返回总览。
- 普通上下滑只滚动内容，不应误触发返回。

### 4.2 固定标题区

标题区不随内容滚动，包含：

- 设备名称。
- 模块 ID。
- `ONLINE` 或 `OFFLINE`。
- 右上角关闭按钮。

### 4.3 可滚动内容区

内容区纵向滚动，每个测量值单独显示：

- 字段名。
- 当前值。
- 单位；只有 capability 明确提供单位时才显示。
- 最近一次成功更新时间或数据年龄。
- 最近约 2 分钟的折线趋势。

不同量纲必须使用独立图表，不能把温度和湿度画在同一个纵轴上。二值量固定为 0–1；其他数据按最近窗口动态缩放并保留约 10% 边距。

字段映射：

| Capability | 字段 |
| --- | --- |
| DHT11 | Temperature (C)、Humidity (%) |
| BH1750 | Illuminance (lux) |
| Vibration | Vibration，二值 |
| Raindrop | Rain，二值 |
| JW01 | CO2、TVOC、CH2O |
| Generic ADC | ADC GPIO4、ADC GPIO5、ADC GPIO6 |
| 未知类型 | Value 1…4，不猜测单位 |

### 4.4 实时更新与历史

- 当前打开的 Sensor 目标约每 1 秒读取一次。
- 其他已显示 Sensor 目标约每 2 秒读取一次。
- 请求串行执行，避免多个 ESP-NOW 请求相互干扰。
- 页面打开时立即显示已有缓存和历史，不需要等待下一次轮询。
- 历史保存在 RAM 中，设备重启后清空。
- 读取失败不写入 0、不推进趋势、也不刷新“最后成功更新时间”。

### 4.5 掉线和恢复

- Sensor 掉线后详情页保持打开。
- 状态显示为红色 `OFFLINE`。
- 保留最后一次有效数据和已有曲线，不用 0 覆盖。
- Sensor 恢复后自动继续读取和更新，无需退出详情页重新进入。

## 5. 非传感器设备的显示规则

Doorbell、纯蜂鸣器和舵机属于执行器，不应为了界面曲线而伪造测量值。

建议的最终规则：

| 设备类别 | 详情页内容 | 趋势图 | 周期读取 |
| --- | --- | --- | --- |
| Sensor | 当前值、单位、更新时间、历史 | 有 | 有 |
| Doorbell / Buzzer | 名称、ID、在线状态、能力、最近命令和结果 | 无 | 无 |
| Servo | 名称、ID、在线状态、当前目标角度/最近命令；有真实位置反馈时才显示反馈 | 默认无 | 默认无 |
| 复合设备 | Sensor 区显示测量值；执行器区显示操作状态 | 只画真实测量值 | 只读取 Sensor 部分 |

当前实现已依据 capability 区分测量设备和纯执行器：纯 Doorbell/Servo 不进入周期读取，详情页显示 `Actuator device / No trend data`；包含真实 Sensor capability 的复合设备仍只绘制测量数据。

## 6. 容量边界

- 通信层当前 `CONFIG_MAX_PEERS=20`，即 Master 的静态 peer 表最多登记 20 台从设备。
- 当前板载 UI 的 `UI_SENSOR_CARD_MAX=4`，只显示和轮询前 4 台。
- 因此当前“通信层最多 20 台，板载屏幕可完整操作 4 台”。
- Kconfig 虽允许调整 peer 表容量，但仅修改 `CONFIG_MAX_PEERS` 不会自动扩大屏幕卡片数，还需要重新设计分页、滚动、内存占用和轮询节奏。

## 7. 实机验收清单

1. 不接从机启动 Master，确认总览正常显示，空卡片不可点击。
2. 查看串口，确认 `CST816D init done`；触摸断开时应有错误但 LCD 仍显示。
3. 连接一台 Sensor，等待不超过一个 announce 周期后出现真实卡片。
4. 点击卡片进入详情，验证右上角关闭和右滑返回。
5. 上下滚动详情，确认不会误返回。
6. 观察当前 Sensor 约 1 秒更新、其他 Sensor 约 2 秒更新。
7. 断开 Sensor，确认 `OFFLINE`、保留最后值；恢复后自动续更。
8. 连接 Doorbell，最终版本应显示执行器详情且没有趋势图和周期读取。
9. 触摸四角，确认坐标方向与屏幕一致；如不一致只调整触摸构建配置。

## 8. 当前已知限制

- 无从机时没有独立的屏幕触摸测试控件，空卡片点击不会提供反馈。
- UI 固定显示 4 台设备，没有第 5 台以后的分页。
- 从机硬件类型仍由 `main/app_main_sensor.cpp` 中的编译期开关选择，尚未做成独立的 Doorbell/Sensor 构建配置。

不同从机的配置与烧录方法见 [slave_firmware_guide.md](slave_firmware_guide.md)。
